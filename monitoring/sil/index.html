    SanitizedSampleReport
        Type: Section
        Role: Content
        Caption: Sanitized Sample Technical Report — ExampleVault.sol ("1-of-N" Demo)
        Purpose: Illustrative example of an execution-verified finding report

        FindingPassport
            Type: Text
            Caption: 1. Finding Passport
            Content: Repository example-defi-protocol (commit a1b2c3d, branch main), component contracts/vault/ExampleVault.sol — claimAndCompound(uint256 amount, uint256 minShares). Defect Class: Reward Debt Accounting Desynchronization. Severity: Medium. Confirmed via local Foundry execution harness without touching mainnet or public testnets.

        SummaryAndRootCause
            Type: Text
            Caption: 2. Summary & Root Cause
            Content: claimAndCompound allows partial reward compounding (amount <= pending), but resets user.rewardDebt using the full updated user.shares balance as if all pending rewards were consumed. The uncompounded remainder (pending - amount) is silently erased from the user's claimable balance and permanently locked in the contract.

        ExecutionTrace
            Type: Text
            Caption: 3. Reproducible PoC & Execution Trace
            Content: Command: forge test --match-test test_ClaimAndCompound_PartialErasesUnclaimedRewards -vvv. With user.shares = 10,000e18 and pending = 500e18, calling claimAndCompound(200e18, 200e18) mints 200e18 shares (user.shares = 10,200e18) and sets user.rewardDebt = 510e18, leaving claimable_after = 0 instead of 300e18. Exactly 300e18 reward tokens (60% of accrued yield) are lost in one valid partial-compound call.

        RefutedByExecution
            Type: Text
            Caption: 4. Candidates Refuted by Execution
            Content: Candidate A (ExampleVault.sol:98 initial deposit rounding) was tested against VIRTUAL_SHARES = 1e6 and VIRTUAL_ASSETS = 1e6, proving any donation attack up to 10,000e18 tokens loses >99.99% of attacker capital (Verdict: SAFE). Candidate B (ExampleVault.sol:211 emergencyWithdraw state ordering) was tested with an ERC-777 callback token, confirming nonReentrant and prior user.shares zeroing at line 206 prevent exploitation (Verdict: SAFE).

        FixAndVerification
            Type: Text
            Caption: 5. Fix Recommendation & Post-Fix Verification
            Content: Compute unpaid = pending - amount and set user.rewardDebt = newBaseline - unpaid. Post-fix test passes and preserves the invariant claimable_before == compounded_amount + claimable_after across 10,000 fuzz runs.

        RemainingTriageCandidates
            Type: Text
            Caption: 6. Remaining Candidates in Triage (1-of-N Rule)
            Content: Candidate #2 in Router.sol (residual ERC-20 allowance after partial multi-hop fill, Medium/Hardening) and Candidate #3 in EpochDistributor.sol (non-strict block.timestamp == epochEnd boundary check, Low/State-transition drift).

        RustWasmSampleReport
            Type: Text
            Caption: Sample Report #2 — Publicly Verifiable Rust / WebAssembly Case (wasm-bindgen Issues #5459, #5460 & Fix PR #5461)
            Content: Publicly verifiable non-security robustness defects found by Sir Revizor in wasm-bindgen/wasm-bindgen: Issue #5459 (https://github.com/wasm-bindgen/wasm-bindgen/issues/5459 — crates/cli-support/src/descriptor.rs:345 panics with "unknown descriptor: 4294967295" and exit code 101 on a minimal 11-byte WASM guest payload pushing 0xFFFFFFFF) and Issue #5460 (https://github.com/wasm-bindgen/wasm-bindgen/issues/5460 — crates/cli-support/src/wit/mod.rs:2989 panics via unwrap() on None when parsing a truncated __wasm_bindgen_unstable custom section), addressed by community fix PR #5461 (https://github.com/wasm-bindgen/wasm-bindgen/pull/5461).
