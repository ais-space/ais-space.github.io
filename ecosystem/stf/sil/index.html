    SpecificationOverview
        Type: Section
        Role: Content
        Caption: STF — Semantic Text Format (Core of the Ecosystem)
        Purpose: Architectural design and guarantees of STF

        SectionTree
            Type: Text
            Caption: Explicit Semantic Section Tree
            Content: STF organizes information as a clean indentation-scoped tree of named semantic sections and key-value properties, eliminating ambiguous delimiters, escaping noise, and closing-tag overhead.

        TrustZones
            Type: Text
            Caption: Trust Zones (System, UserContent, and Others)
            Content: Every section in STF belongs to an explicit provenance and trust zone such as System or UserContent, making authority boundaries first-class syntactic properties rather than informal prompt conventions.

        PromptInjectionDefense
            Type: Text
            Caption: Native EBNF Syntactic Defense Against Prompt Injection
            Content: Because trust boundaries are enforced at the EBNF grammar syntax level, untrusted text inside a UserContent branch cannot syntactically escape its subtree or forge System instructions.

        InferenceEfficiency
            Type: Text
            Caption: Reduced Inference Cost for Smaller Models
            Content: By removing visual markup clutter and deep punctuation nesting, STF reduces token footprint and cognitive load, enabling smaller models to parse and generate structured documents reliably at lower inference cost.

        StructureExample
            Type: Text
            Caption: Example STF Document Structure
            Content: An STF document begins with a Context block (Version, Document, Language, Origin: System) followed by hierarchical sections where authoritative PolicySection (Origin: System) and untrusted IncomingSubmission (Origin: UserContent) are strictly separated by grammar.
