The STF Ecosystem — Pure Grammar-Level Semantics for AI Agents

Existing user interfaces, document formats, and programming languages were engineered around human sensory perception and visual layout. The STF ecosystem replaces visual heuristics with explicit, deterministic semantics encoded directly into the grammar.

Start with STF Core → GitHub: github.com/ais-space Read SIL Layer (/ecosystem/sil/)

Why AI Agents Need Native Semantic Infrastructure

Human-Centric Formats vs. Agent-Native Grammar

HTML, CSS, DOM trees, Markdown, and traditional source syntaxes evolved for human eyes. When an AI agent interacts with a modern web application or maintains a large system over long sessions, it is forced to burn tokens reconstructing intent from visual layout tags, deeply nested punctuation, untrusted string concatenations, and flat chat logs.

  • No Visual Guesswork: Instead of reverse-engineering <div> hierarchies and JavaScript bundles, an agent reads explicit intent, roles, actions, and navigation targets directly from the document grammar.
  • Grammar-Enforced Trust Boundaries: Data provenance and trust zones (such as System vs. UserContent) are syntactic primitives in the EBNF grammar, eliminating ambiguity between instructions and untrusted payloads.
  • Resilience Under Context Compression: Because every node carries self-contained semantic keys rather than position-sensitive punctuation, even smaller models and sessions undergoing repeated context autocompression preserve structural soundness.

The 5 Ecosystem Components

1. STF — Semantic Text Format (Foundation)

The core structural language of the ecosystem. Represents documents as an explicit tree of named semantic sections with built-in trust zones (System, UserContent, and others), providing native syntactic defense against prompt injections at the EBNF grammar level and significantly reducing inference cost for smaller language models.

Explore STF → SIL: /ecosystem/stf/index.sil · github.com/ais-space/stf

2. SIL — Semantic Interface Layer (Web & Application Interface)

An application extension of STF designed for AI agent web navigation without parsing raw HTML/DOM or executing client-side JavaScript. Defines 5 conformance profiles ranging from read-only content discovery to interactive stateful workflows. Every page on ais-platform.dev publishes a live SIL representation alongside HTML.

Explore SIL → SIL: /ecosystem/sil/index.sil · github.com/ais-space/sil

3. STF-Memory — Structured Long-Term Agent Memory

A state-oriented memory architecture built on STF that replaces append-only flat transcript logs with explicit fact records, conflict detection and resolution, trust provenance, and task-specific projections — preventing memory drift and context degradation in long-horizon multi-agent runs.

Explore STF-Memory → SIL: /ecosystem/stf-memory/index.sil · github.com/ais-space/stf-memory

4. SIR — Semantic Intermediate Representation

An executable semantic intermediate representation layered over STF for AI coding agents. Replaces fragile punctuation-heavy syntax with explicit semantic blocks for types, functions, control flow, and memory operations, enabling verifiable translation directly to WebAssembly.

Explore SIR → SIL: /ecosystem/sir/index.sil · github.com/ais-space/sir

5. SIR Compiler — Self-Hosting SIR→WASM Compiler

A self-compiling SIR-to-WebAssembly compiler written in SIR itself (~103 KB binary, proven byte-for-byte self-compilation fixpoint, 253/253 tests passing). Built to prove the practical durability of the SIR architecture when authored by compact models across repeated context autocompressions without re-reading the language specification.

Explore SIR Compiler → SIL: /ecosystem/sir-compiler/index.sil · github.com/ais-space/sir-compiler
